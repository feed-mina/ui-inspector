## 4. 수정 또는 확인 방법

1. 로컬 SQLite와 가상 페이지로 저장·조회 계약을 먼저 확인합니다.
2. 배포 환경의 도메인·허용 출처·접근 제한을 확인합니다.
3. 허가된 테스트 핀으로 실제 왕복을 확인하고 운영 버전을 기록합니다.

## 5. 완료 기준

- [ ] 정상 저장은 id와 created=true를 반환하고 다시 조회하면 해당 핀이 보입니다.
- [ ] 다른 페이지의 ID 수정은 404로 끝납니다.
- [ ] 접근 제한과 허용 출처가 실제 환경에서 적용됩니다.

## 6. 검증 방법과 제출할 근거

backend의 tests/test_api.py와 test_contract.py를 실행하고 API 왕복 결과를 남깁니다. 이 보고서의 문서 완료 상태와 운영 배포 확인 상태는 별도로 유지합니다.

실행 결과·캡처·응답 본문 중 완료 기준에 해당하는 근거를 남깁니다. 미실행 항목은 완료로 표시하지 않습니다.
